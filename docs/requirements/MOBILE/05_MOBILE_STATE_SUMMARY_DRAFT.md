# MOBILE 상태값 정리 — 중앙 판단 기능 전달용

> 목적: 중앙 판단 기능이 전체 구조를 설계할 수 있도록 **모바일 인터페이스가 주고받는 상태값만 한 장으로 정리**한다.
> 본 문서는 `01`~`04` 에서 파생된 요약이며 새로운 요구사항을 정의하지 않는다.
> 원문은 `02_MOBILE_SYSRS_FUNCTIONAL_BASELINE_DRAFT` 3절 · 8절, `03_MOBILE_LOGICAL_INTERFACE_NEEDS` 2절 · 3절.
> 무선 방식, 데이터 형식, 송신 주기는 본 단계에서 확정하지 않는다.

**모바일은 차량 노드와 직접 통신하지 않는다.** 게이트웨이를 거쳐 중앙 판단 기능과 주고받는 것을 전제로 한다.

---

## 1. MOBILE → 중앙 (앱이 보내는 것)

앱은 **요청을 생성할 뿐이며 허용 여부와 실제 수행은 차량이 결정한다.**

| 항목 | 값 집합 | 비고 |
|---|---|---|
| 도어 제어 요청 | `LOCK` / `UNLOCK` | |
| 목표 온도 | 수치 (°C) | 범위는 미정 |
| 자동 공조 사용 여부 | `ON` / `OFF` | |
| 공기 순환 세기 요청 | `OFF` / `LOW` / `MEDIUM` / `HIGH` | BCM 의 Fan 수준과 동일 집합 |
| 탑승 예정 시각 | 시각 | 표현 형식 미정 |
| 선행 공조 사용 여부 | `ON` / `OFF` | |
| 선행 공조 정지 요청 | 트리거 | 수행 중인 것만 대상 |
| 조명 사용 여부 · 밝기 · 색상 | `ON`/`OFF` · 수준 · 색 | 색상 표현 미정 |
| 제어 요청 식별자 | 중복·순서 판별 가능한 값 | 모든 요청에 포함 |
| 인증 응답 | 인증 절차에 필요한 값 | 프로토콜 미정 |

## 2. 중앙 → MOBILE (앱이 받아야 하는 것)

### 2.1 실행 상태 — 출처 `BCM`

| 항목 | 값 집합 |
|---|---|
| 도어 잠금 상태 | `LOCKED` / `UNLOCKED` / `UNKNOWN` |
| 도어 개폐 상태 | `CLOSED` / `OPEN` / `UNKNOWN` |
| 도어 종합 상태 비정상 여부 | `NORMAL` / `INCONSISTENT` / `UNTRUSTED` |
| Fan 요구 수준 · 측정 수준 | 각각 `OFF` / `LOW` / `MEDIUM` / `HIGH` (측정은 `UNKNOWN` 포함) |
| 온도 장치 방향 · 출력 수준 | `COOL`/`HEAT`/`IDLE` · `0`/`30`/`50`/`최대` (%) |
| 조명 사용 설정 · 밝기 · 현재 알림 종류 | `ON`/`OFF` · `25`~`100` % · 6종 |

### 2.2 센싱 — 출처 `CIS`

| 항목 | 값 집합 |
|---|---|
| 현재 실내 온도 | 수치 (°C) |
| 차량이 확정한 실내 환경 정보 | 미정 |
| 탑승자 유무 | `있음` / `없음` / `확인 불가` |

### 2.3 타 기능 — 출처 미정 / `VSS`

| 항목 | 출처 | 비고 |
|---|---|---|
| 창문 동작 상태 · 요청 처리 결과 | **TBD — 담당 노드 미정** | 앱이 표시해야 하나 제공처가 정해지지 않음 |
| 음향 기능 오류 | `VSS` | |

### 2.4 판단 결과 및 공통 — 출처 `중앙`

| 항목 | 값 집합 | 비고 |
|---|---|---|
| 설정된 목표 온도 · 자동 공조 사용 여부 | 수치 · `ON`/`OFF` | 앱이 보낸 설정의 확정본 |
| 선행 공조 수행 상태 · 탑승 예정 시각 | 상태 · 시각 | |
| 제어 요청 처리 결과 | `SENT` / `ACCEPTED` / `IN_PROGRESS` / `DONE` / `REJECTED` / `FAILED` / `CANCELLED` / `UNKNOWN` | `UNKNOWN` 은 앱이 자체 판정 |
| 거부 · 실패 · 중단 사유 | 표시 가능한 의미 코드 | 코드 체계 미정 |
| 안전 관련 경고 | 등급이 구분된 의미 상태 | 등급 정의 미정 |
| 오류 분류 | `SENSOR` / `COMM` / `FUNCTION` | 전 노드 공통 |
| 각 상태값의 신뢰성 | `OK` / `STALE` / `INVALID` / `NO_DATA` | **모든 상태값에 동반** |
| 각 상태값의 최신 판단 근거 | 신선도 판정 가능한 값 | 무선 지연 검출에 필요 |

## 3. 앱이 자체적으로 관리하는 상태

중앙이 보낼 필요가 없는 값이다.

| 항목 | 값 집합 | 비고 |
|---|---|---|
| 연결 상태 | `DISCONNECTED` / `CONNECTING` / `CONNECTED` / `AUTHENTICATED` | |
| 요청 `UNKNOWN` 전이 | 결과 미수신 타임아웃 | 차량이 보내는 값이 아님 |
| 경고 확인 상태 | `UNREAD` / `READ` | 확인해도 경고 상태 자체는 해제되지 않음 |
| 표시 신뢰성 | 수신 신뢰성 + 무선 구간 신선도 | 차량이 `OK` 로 보내도 무선 지연 시 `STALE` 처리 |

**`UNKNOWN` 과 `READ` 는 차량이 관여하지 않는다.** 요청 결과를 확인하지 못한 것과
실패한 것은 다르므로 `DONE` / `FAILED` 로 임의 분류하지 않는다.

## 5. 확인 요청

| 항목 | 사유 |
|---|---|
| 상태 송신 주기 | 이 값이 정해져야 `STALE` 판정 시간을 확정할 수 있다. 현재 잠정 2 s |
| 경고 등급 정의 | 등급 구분이 없으면 안전 경고를 일반 상태보다 우선 표시할 수 없다 |
| 거부 · 실패 사유 코드 체계 | 사용자에게 표시할 문구로 바꾸려면 의미 코드가 필요하다 |
| 창문 상태의 출처 | 앱이 표시해야 하는 항목인데 제공 노드가 정해지지 않았다 |
| 게이트웨이 담당 | 앱과 차량 사이 구간을 누가 맡는지 미정 |
