# BCM 상태값 정리 — 중앙 판단 기능 전달용

> 목적: 중앙 판단 기능이 전체 구조를 설계할 수 있도록 **BCM이 주고받는 상태값만 한 장으로 정리**한다.
> 본 문서는 `01`~`04` 에서 파생된 요약이며 새로운 요구사항을 정의하지 않는다.
> 원문은 `02_BCM_SYSRS_FUNCTIONAL_BASELINE_DRAFT` 3절 · 8절, `03_BCM_LOGICAL_INTERFACE_NEEDS` 2절 · 3절.
> 값의 수치 인코딩, 메시지 배치, 송신 주기는 본 단계에서 확정하지 않는다.

---

## 1. 중앙 → BCM (BCM이 받아야 하는 것)

BCM은 **이미 확정된 동작**만 받는다. 센싱 값이나 판단 근거는 받지 않는다.

| 항목 | 값 집합 | 비고 |
|---|---|---|
| 도어 잠금 목표 상태 | `LOCK` / `UNLOCK` | |
| Fan 지시 출력 수준 | `OFF` / `LOW` / `MEDIUM` / `HIGH` | 4단계 |
| 온도 장치 동작 방향 | `COOL` / `HEAT` / `IDLE` | |
| 온도 장치 출력 수준 | `0` / `30` / `50` / `최대` (%) | 최대는 방열 구성에 따라 제한 |
| 조명 알림 종류 | `NORMAL` / `GOODBYE` / `WARNING` / `FAULT` | 4종 |
| 조명 출력 수준 | `25` / `50` / `75` / `100` (%) | |
| 명령 식별자 | 중복·역순 판별 가능한 값 | 모든 명령에 포함 |
| 명령 유효 상태 근거 | 신선도 판정이 가능한 값 | 예: 카운터 · 타임스탬프 |

**BCM이 받지 않는 것** — 실내 온도, 조도, 탑승자 유무 등 센싱 값. 목표 온도 등 사용자 설정.
이들로부터 지시 수준을 산출하는 것은 중앙의 범위이며, 산출 기준은 `03` 4절에 정리했다.

---

## 2. BCM → 중앙 (BCM이 제공하는 것)

### 2.1 도어

| 항목 | 값 집합 | 비고 |
|---|---|---|
| 도어 잠금 상태 | `LOCKED` / `UNLOCKED` / `UNKNOWN` | 잠금 접점 |
| 도어 개폐 상태 | `CLOSED` / `OPEN` / `UNKNOWN` | 개폐 접점. 잠금과 독립 입력 |
| 도어 종합 상태 | `NORMAL` / `INCONSISTENT` / `UNTRUSTED` | 두 접점 조합으로 산출 |

`LOCKED` + `OPEN` 조합은 물리적으로 성립하지 않으므로 `INCONSISTENT` 로 관리한다.
둘 중 하나라도 `UNKNOWN` 이면 `UNTRUSTED` 이다.

### 2.2 명령 처리 결과

| 항목 | 값 집합 |
|---|---|
| 명령 처리 결과 | `ACCEPTED` / `IN_PROGRESS` / `DONE` / `REJECTED` / `FAILED` |
| 거부 사유 | `DOOR_OPEN` / `STATE_UNTRUSTED` / `ALREADY_AT_TARGET` / `CMD_INVALID` |
| 실패 사유 | `NO_FEEDBACK` / `DRIVE_LIMIT_EXCEEDED` |

`ALREADY_AT_TARGET` 은 구동 없이 완료 처리된 경우이며 오류가 아니다.
자체 안전 판단에 의한 거부(`DOOR_OPEN`)도 BCM 오류로 분류하지 않는다.

### 2.3 공조

| 항목 | 값 집합 | 비고 |
|---|---|---|
| Fan 지시 수준 | `OFF` / `LOW` / `MEDIUM` / `HIGH` | 수신한 명령을 보관한 값 |
| Fan 측정 수준 | `OFF` / `LOW` / `MEDIUM` / `HIGH` / `UNKNOWN` | 실제 회전을 측정해 분류 |
| 온도 장치 방향 | `COOL` / `HEAT` / `IDLE` | |
| 온도 장치 출력 수준 | `0` / `30` / `50` / `최대` (%) | |
| 열 제거 수단 상태 | `정상` / `과열 차단` / `측정 불가` | 방열부 온도에서 산출 |

**지시 수준과 측정 수준을 별도 항목으로 제공한다.** 하나로 합치면 불일치를 검출할 수 없다.

### 2.4 조명

| 항목 | 값 집합 |
|---|---|
| 현재 적용 중인 알림 종류 | `NORMAL` / `GOODBYE` / `WARNING` / `FAULT` |
| 현재 출력 수준 | `25` / `50` / `75` / `100` (%) |

### 2.5 공통

| 항목 | 값 집합 | 비고 |
|---|---|---|
| ECU 동작 상태 | `INIT` / `READY` / `DEGRADED` / `FAULT` | `DEGRADED` = 일부 기능만 정지 |
| 오류 분류 | `SENSOR` / `COMM` / `FUNCTION` | |
| 각 상태값의 유효 상태 | `OK` / `STALE` / `INVALID` / `NO_DATA` | **모든 상태값에 동반** |

`유효 상태`는 값과 분리하지 않고 함께 전달한다. 분리되면 수신 측에서 신뢰성 표시가 누락된다.

## 3. 중앙이 결정해야 하는 것

`03_BCM_LOGICAL_INTERFACE_NEEDS` 4절에 산출 기준을 제안해 두었다.
값은 액추에이터 특성에서 나온 것이며 벤치 측정 후 확정한다.

| 결정 항목 | 입력 | 출력 | 제안 기준 |
|---|---|---|---|
| Fan 출력 수준 | 실내 온도 · 목표 온도 | `OFF`~`HIGH` | ΔT 0.5 / 2.0 / 4.0 °C · 히스테리시스 0.3 °C |
| 온도 장치 방향·출력 | 실내 온도 · 목표 온도 | 방향 + 수준 | 불감대 ± 0.5 °C · 30 / 50 / 최대 |
| 조명 알림 우선순위 | 각 기능의 표시 요구 | 알림 종류 1개 | `NORMAL` 0 → `FAULT` 3 |
| 조명 출력 수준 | 실내 조도 | 25~100 % | 30 / 300 / 3000 lux · 히스테리시스 30 % |
| 도어 명령 허용 조건 | 차량 상태 | 명령 생성 여부 | BCM 거부 조건과 동일하게 사전 확인 권장 |
| 공조 자원 중재 | 복수 기능의 공조 요구 | 지시 1개 | Fan · 온도 장치는 각 1개뿐 |

**히스테리시스 0.3 °C 의 근거** — 온도 센서 공차가 ± 0.23 °C 이므로 그보다 좁은 간격으로
수준을 전환하면 센서 잡음만으로 단계가 반복 전환된다.

## 4. 본 단계에서 확정하지 않은 것

| 항목 | 상태 |
|---|---|
| 값의 수치 인코딩 (열거값 → 정수) | NOT DEFINED |
| 메시지 ID · 신호 배치 · DLC | NOT DEFINED |
| 송신 주기 · Timeout | NOT DEFINED |
| Alive Counter · CRC / E2E | NOT DEFINED |
| 물리 계층 (CAN / LIN / UART) | NOT DEFINED |
| 명령 식별자 폭 및 순환 방식 | NOT DEFINED |

**상태 정보는 변화 시점과 주기 양쪽에서 제공하는 것을 전제로 작성했다.**
조명 알림 지시처럼 즉시성이 필요한 항목은 주기 전송을 기다리지 않고 전달되어야 한다.

## 5. 확인 요청

| 항목 | 사유 |
|---|---|
| 3절 판단 기준 6건의 수용 여부 | 수용되지 않으면 BCM 이 센싱 값을 받는 구조로 SR 부터 재작성 필요 |
| 송신 주기 | 이 값이 정해져야 `STALE` 판정 기준과 미수신 허용 횟수를 확정할 수 있다 |
| 오류 분류 열거값 | 노드마다 다르면 수신 측에서 구분 표시가 불가능하다 |
| 중앙 보드 구성 | VSS SysRS 가 S32K344 전용 ECU 로 선언되어 있어 보드 공유 여부 확인 필요 |
