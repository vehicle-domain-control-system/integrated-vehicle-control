# MOBILE — Interface 정보 (Domain 전달용)

> ECU Interface 가이드의 7개 항목 양식을 따르되, MOBILE은 ECU가 아니라 **요청을 생성하는 쪽**이므로 방향이 반대다.
> Request = MOBILE → Domain, State/Event = Domain → MOBILE 로 읽는다. 게이트웨이(BLE)를 경유한다.
> 근거: `SR §7 MOBILE 기능 요구`, `sysRS §6 MOBILE 상세 요구사항`.

---

## 1. 주요 기능

- 사용자 제어 요청 생성 (도어·공조·조명·디지털 키 설정)
- 차량 상태·처리 결과·경고 표시 (신뢰성 구분 포함)
- 차량 연결 관리 (등록·인증·재연결)

MOBILE은 **요청을 생성할 뿐** 차량 기능을 직접 수행하지 않는다. 상태를 자체 추정·보정하지 않으며, 허용 여부 판단과 근접 판정은 차량 측이 수행한다.

---

## 2. State (MOBILE 내부 상태)

- 연결 상태: `DISCONNECTED` / `CONNECTING` / `CONNECTED` / `AUTHENTICATED`
- 요청 상태: `SENT` / `ACCEPTED` / `IN_PROGRESS` / `DONE` / `REJECTED` / `FAILED` / `CANCELLED` / `UNKNOWN`
  - `UNKNOWN` = 전송했으나 결과 미확인 — `DONE`/`FAILED`로 임의 분류하지 않음
- 표시 값 신뢰성: `OK` / `STALE` / `INVALID` / `NO_DATA` (수신한 모든 차량 상태에 동반)
- 경고 확인 상태: `UNREAD` / `READ` (READ ≠ 경고 해제)

---

## 3. Request / Command (MOBILE → Domain)

모든 요청에 **요청 식별자**(중복·역순 판별) 포함. 연결 상태가 `AUTHENTICATED`가 아니면 생성하지 않는다.

- 도어: `LOCK` / `UNLOCK`
- 목표 온도 설정 + 자동 공조 사용 여부
- 실내 공기 순환 세기: `OFF` / `LOW` / `MEDIUM` / `HIGH`
- 실내 조명: 사용 여부 + 밝기(0~100 %) + 색상(R/G/B, NORMAL 전용)
- 근접 자동 잠금 해제 사용 여부: `ON` / `OFF`

> MOBILE이 보내는 것은 **사용자 설정·요청**이다. 이를 BCM 지시로 변환하는 것은 중앙의 몫.

---

## 4. Event (Domain → MOBILE, 표시 대상)

- 요청 결과 통지: 접수·진행·완료·거부(+사유)·실패(+사유)·중단
- 안전 경고: 이탈 후 도어 열림 유지, 안전 보호 동작 발생
- 근접 잠금 해제 발생 — 사용자 요청에 의한 해제와 **구분 표시**
- 상태 변화 통지: 각 기능의 상태·오류 갱신

---

## 5. Fault (MOBILE이 감지·표시하는 것)

- `COMM_FAULT` — 게이트웨이 연결 두절
- `AUTH_FAULT` — 인증 실패 (자동 재시도로 우회 금지)
- `RESULT_TIMEOUT_FAULT` — 요청 결과 대기 초과 → 해당 요청 `UNKNOWN`
- 차량 측 오류의 구분 표시: `SENSOR` / `COMM` / `FUNCTION` (차량이 분류해 제공)

---

## 6. Data

### Data 1

```text
Name  : 목표 온도
Type  : int8 또는 0.5 단위 (예상)
Range : 차량 정책 범위 (중앙과 합의 필요)
Unit  : °C
Desc  : 사용자 설정. 실제 반영 여부는 차량 결정
```

### Data 2

```text
Name  : 조명 밝기 / 색상
Type  : uint8 / uint8 × 3
Range : 0 ~ 100 각각
Unit  : %
Desc  : 색상은 NORMAL 알림에만 적용됨을 UI 에서 안내
```

### Data 3 (수신·표시)

```text
Name  : 실내 온도 (표시용)
Unit  : °C
Desc  : 차량이 확정해 제공. 신뢰성·수신 시점 함께 표시,
        STALE 이면 마지막 수신 시점 병기
```

---

## 7. Local Logic

- **무선 구간 신선도 재판정** — 차량이 `OK`로 보낸 값도 수신 지연 시 `STALE`로 강등해 표시
- **요청 식별자 생성·수명 관리** — 재전송 시 동일 식별자 유지 (차량 중복 실행 방지)
- **UNKNOWN 관리** — 자동 재전송 금지, 재요청은 사용자 조작으로만
- **재연결** — 횟수·시간 제한된 자동 재연결, 한도 도달 시 사유 표시 후 사용자 대기. 사용자의 연결 해제·인증 실패는 자동 재시도로 우회하지 않음
- **신뢰성별 표시 규칙** — `INVALID`/`NO_DATA`는 수치 미표시, 경고는 일반 상태보다 우선 배치
- **BLE 응답 가능 상태 유지** — 등록 상태에서 차량이 단말을 식별할 수 있도록 유지 (근접 판정 자체는 차량 측)

---

## 8. Fail-safe

- **연결 두절** → 제어 요청 생성 중단 + 사유 표시, 마지막 값을 현재 정상으로 표시하지 않음
- **연결 복구** → 차량 최신 상태로 갱신. **복구만을 근거로 이전 요청 재전송 금지**
- **결과 미수신** → `UNKNOWN` 유지, 성공/실패로 단정하지 않음
- **인증 실패** → 요청 차단 + 사유 표시, 인증 정보 노출 없이
- **등록 해제** → 등록 정보 삭제, 연결·새 요청·BLE 응답 유지 중단 (디지털 키 무효화)
